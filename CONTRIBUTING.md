# Contributing to Quire

Thank you for helping! Each repository can have its own guide with the details of how to set it up and test it; the one for Quire itself is [quirecms/framework's CONTRIBUTING.md](https://github.com/quirecms/framework/blob/main/CONTRIBUTING.md). What follows applies everywhere.

## Before you start

- **Bugs:** search the existing issues first. If nobody has reported it, open an issue with the steps to reproduce it.
- **Features and bigger changes:** open an issue describing the problem you want to solve before you write code, so we can agree on the approach. A pull request for an unplanned feature may be declined, however good the code.
- **Security issues:** don't open an issue; follow the [security policy](SECURITY.md).

## Pull requests

- One topic per pull request, with tests for what it changes, and documentation when users notice the change.
- The checks in CI must pass.
- Write the description for a reviewer who hasn't seen the issue: what changes, why, and how you tested it.

## Code of conduct

Everyone taking part in the project follows the [code of conduct](CODE_OF_CONDUCT.md).
